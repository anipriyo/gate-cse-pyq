# site

Static single-page app, no build step. GitHub Pages serves the `gh-pages` branch (just this folder); redeploy with `git subtree push --prefix site origin gh-pages` from the repo root after committing.

| File | Role |
|---|---|
| `index.html` | Shell; loads KaTeX 0.16.11 from jsDelivr and `js/app.js`. |
| `js/util.js` | Data loading (`data/questions.json`), localStorage wrapper, GATE scoring (`verdict`, `marksFor`), KaTeX rendering of `[latex]…[/latex]`, HTML sanitising. |
| `js/app.js` | Hash router and views: home, practice builder, practice runner, results, mock list, progress. |
| `js/exam.js` | GATE-style mock console (instructions page, timer, sections, palette, Save & Next rules, submit summary). |
| `js/syllabus.js` | Syllabus page: official lines, linked topics with PYQ counts and accuracy, tick-as-studied (`gatepyq.syllabus.studied`), buttons that pre-fill the practice builder. |
| `js/ai.js` | AI tutor (desktop app only; see `app/README.md`). |
| `js/calc.js` | Scientific calculator with its own expression parser. |
| `css/app.css`, `css/exam.css` | Styles. The app follows light/dark; the exam console is light-only like the real one. |
| `data/` | Generated by `scraper/build_db.py`; do not edit by hand. |

Scoring follows GATE: MCQ wrong answers lose 1/3 of the question's marks; MSQ needs the exact set; NAT accepts the official range; MSQ and NAT have no negative marks. In mocks only saved answers count, and "marked for review" without an answer is not evaluated.

localStorage keys (prefix `gatepyq.`): `results`, `qstats` (per-question last verdict), `bookmarks`, `builder` (last filter), `session.practice`, `session.exam`, `theme`, `syllabus.studied`, `ai.chats`.

The loader keeps two lists: `DB.all` (every question, used by mocks and results) and `DB.questions` (the practice pool, `mock_only` excluded). Practice, progress and the syllabus use only the pool.

Preview locally:

```bash
~/.venvs/analysis/bin/python -m http.server 8765 --directory site
```
